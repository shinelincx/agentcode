# 节点逻辑规则与优化候选

本页回答「各节点逻辑规则如何设置、如何优化、能否可视化」。事实部分逐条对应代码；优化项为建议，未获实施批准。

## 一、规则分三层

| 层 | 载体 | 是否可配置 |
| --- | --- | --- |
| 图结构（节点、边、失败出口） | [graph.py](../../../platform/graph.py) `build_app` | 否，硬编码 |
| 节点内部规则（阈值、章节、关键词、命令、重试次数） | `graph.py` 顶部常量与各节点函数 | 部分：`implement`/`test` 门禁命令改由 `tech_stack.gate_commands` 驱动；阈值、章节、关键词仍硬编码 |
| 运营参数（预算、模型路由、测试门禁、staging、审批人/SLA） | `projects/<proj>/project.yaml`，控制台 `/config` 可改 | 部分：`budget.monthly_quota` / `max_usage_per_task`、`model.*`、`test.gates`、`deploy.staging` 实际生效；`budget.thresholds`、`budget.max_inflight_tasks`、`gates.*.sla_hours` 目前只被校验/展示，无消费方 |

## 二、逐节点规则

| 节点 | 前置校验 | 主要动作 | 通过条件 | 失败 / 例外 |
| --- | --- | --- | --- | --- |
| `requirements` | `state.requirement` 非空，否则 `requirement_input` FAIL | codex（`requirements-gen` 1.1.0，`-s read-only`）→ 抽取 Markdown | `_doc_gate`：80–50,000 字符、含 `## 需求`/`## 验收标准`/`## 非目标`；`doc_repo_clean`：收尾比对脏文件，改动项目仓库即 FAIL（G-01） | 直接 `gate_failed`，条件边到 END，不进 G1 |
| `review_g1` | — | `interrupt` 挂起 | 人工 `approved` | `rejected` → 回 `requirements` 重生成 |
| `design` | `requirements_doc` 文件可读，否则 `design_input` FAIL | codex（`design-gen` 1.1.0，`-s read-only`） | `_doc_gate`：含 `## 文件归属表`/`## 实现策略`/`## 验收映射`；`design_ac_coverage`：需求的 AC-n 全部出现在验收映射；`doc_repo_clean` 同 requirements | 同上，不进 G2 |
| `prototype` | `design_doc` 可读，否则 `prototype_input` FAIL | `_needs_prototype` 判定 → 清理仓库内 `.agentcode-prototype/*` 崩溃残留 → codex（`prototype-gen` 1.1.0）写 `index.html`/`PROTOTYPE.md`，或写跳过说明 | `prototype_files`：HTML 200–300,000 字符且含 `<html>`；MD ≥80 字符且含「原型说明/验收映射/局限」 | 执行异常/门禁失败 → `gate_failed`；跳过仍记 `prototype_skipped` PASS 并进 G2 |
| `review_g2` | — | `interrupt` 挂起 | 人工 `approved` | `rejected` → 回 `design`（原型随之重跑） |
| `implement` | lanes 来源：`state.lanes` → DESIGN 归属表 → 默认占位 | 每 lane：`checkout -B` → 预算/U 检查 → **推导 lane 根作为 codex cwd（`_lane_workdir`，多根/通配/缺失/逃生口回退仓库根）** → codex（`implement-lane` 1.2.0）→ 空交付检测 → **`lane_workdir_prefix` 嵌套前缀校验** → **`lane_scope` 越界校验** → typecheck/unit 门禁（命令读 `tech_stack.gate_commands`，失败修正 1 次，`gate-fix` 1.2.0）→ commit | 门禁全过且 commit rc=0 | 任一步失败 → `gate_failed`；预算 PAUSED/低优先级 → `awaiting_human` |
| `review` | 任务状态不得为 `awaiting_human/gate_failed/failed/done` | 确定性核对（零成本）：提交清单、`base..HEAD` 变更文件 vs lane scope、AC 覆盖；`review.codex: true` 时追加 codex（`review-diff` 1.2.1，含 diff + 变更文件完整内容 + implement 门禁结果），写 `REVIEW.md` / `REVIEW-agent.md` | `review_commits`/`review_lane_scope`/`review_ac_coverage`/`review_agent` 全 PASS | 任一失败 → `gate_failed`，不进 `test`；预算 PAUSED → `awaiting_human` |
| `test` | 任务状态不得为 `awaiting_human/gate_failed/failed/done` | 按 `test.gates` 在编排层跑命令，写 `TEST_REPORT.md`（不调 codex） | 全部门禁 PASS 且门禁列表非空 | 任一失败 → `gate_failed`，不进部署 |
| `deploy` | 同上状态守卫 | 按 `deploy.staging` 依次执行 commands → smoke → healthcheck，写 `DEPLOY_REPORT.md` | 全部 PASS | 失败 → `gate_failed`；`required=true` 未配置 → 转人审；`required=false` 未配置 → 显式跳过（`deploy_skipped`） |
| `review_g3` | — | `interrupt` 挂起，审批物为部署报告 | 人工 `approved` | `rejected` → 回 `implement` 重跑 test/deploy |
| `retro` | 状态非 `awaiting_human/gate_failed/failed` | 登记租约 → `retro.generate: true` 时 codex（`retro-gen` 1.2.0，`-s read-only`）生成 `RETRO.md`；否则状态盖章 | 收尾成功；`retro_doc` 仅留痕，不决定终态 | 终态守卫直接返回，不覆盖失败状态；复盘生成失败不改 `done` |

横切规则：

- **预算**：`evaluate_budget` 按累计 calls / quota 定 NORMAL→ALERT→DEGRADED→PAUSED；`start_node_run` 在 PAUSED 时拒发，ALERT/DEGRADED 时拒发低优先级任务；`implement` 另查单任务上限 U。
- **模型路由**：NORMAL/ALERT 及 DEGRADED 强角色优先走 `model.roles.<role>`，未声明时继承 `model.default`；DEGRADED 时非 `strong_roles` 走 `model.degraded`。requirements/design/prototype/implement/review/retro 的实际 codex 调用统一经 `route_model`，test/deploy 当前不调 LLM。
- **租约**：全部执行节点（`requirements`/`design`/`prototype`/`implement`/`review`/`test`/`deploy`/`retro`）统一走 Worker + epoch 栅栏；`test`/`deploy` 不调用 codex，跳过凭据目录复制（`_start_leased_run(with_codex_home=False)`）。
- **审批哈希**：G1 绑 `REQUIREMENTS.md`；G2 绑 `DESIGN.md` + 原型目录；G3 绑 `DEPLOY_REPORT.md`。

| P2 | `_needs_prototype` 用正则匹配表格第二列，表格列序变化即失效；归属表存在但无 be/fe 时静默回退关键词 | **已解决（2026-11-12）**：改为解析 Markdown 表头定位 lane 列（支持 `前端/后端`、`frontend` 别名，列序无关）；缺 lane 列或无有效数据行时返回 `None`，`prototype` 记 `prototype_scope` 门禁失败并阻断 G2，不再猜测列位 |
| P2 | 文档门禁只校验骨架（长度+章节），不校验内容与 AC 的对应关系 | **已解决（2026-11-12，A 层）**：`design_ac_coverage` 机械核对 AC-n 是否出现在验收映射 |
| P2 | `test`/`deploy` 未接租约，与其余节点语义不一致 | **已解决（2026-11-12）**：两节点改用 `_start_leased_run` / `_close`，部署操作登记带 `worker_id + lease_epoch` 栅栏 |

## 四、可视化现状与建议

已具备（事实）：

- 控制台任务表 10 步流程胶囊、`/api/task/detail` 节点时间线、门禁与审批面板（[[平台看板]]）。
- 但 `FLOW_NODES`、`KINDS`、节点展示名均在前端/后端硬编码（[dashboard.py](../../../platform/dashboard.py)），规则改动不会自动反映到界面。

建议：

1. 从 `graph.py` 导出只读的图规格（节点、边、闸门、门禁阈值、失败出口）为 `/api/graph-spec`，前端据此渲染，消除双份硬编码。
2. 看板节点详情增加「本轮判定理由」列：`_needs_prototype`、门禁 reason 已入账，可直接展示，便于解释为什么生成/跳过了原型。
3. 可选：Mermaid/SVG 自动生成整图，用于文档与评审，避免手绘与代码漂移。

## 五、Prompt 覆盖与优化方案

### 谁有 prompt（事实）

| 角色 | 调用模型 | 模板 | 说明 |
| --- | --- | --- | --- |
| requirements | codex | `requirements-gen` 1.1.0 | 原始需求 → REQUIREMENTS.md |
| design | codex | `design-gen` 1.1.0 | REQUIREMENTS → DESIGN.md |
| prototype | codex | `prototype-gen` 1.1.0 | 设计 + 需求 → index.html + PROTOTYPE.md |
| implement（每 lane） | codex | `implement-lane` 1.1.0（`LANES[].prompt` 可绕过） | 每个 lane 一次调用 |
| implement 修正循环 | codex | `gate-fix` 1.1.0 | 门禁失败后最多 1 次 |
| review | codex（可选，`review.codex: true`） | `review-diff` 1.2.1 | 审交付 diff + 变更文件完整内容 + implement 门禁结果，PASS/FAIL 决定是否进 `test` |
| retro | codex（可选，`retro.generate: true`） | `retro-gen` 1.2.0 | 生成 `RETRO.md`，失败不改交付终态 |
| test / deploy / G1-G3 / 确定性审查部分 | 不调模型 | 无 | 门禁命令、`interrupt`、状态盖章属确定性编排 |

`review` 角色名已由图节点消费；`strong_roles` 的降级豁免仍按配置生效。

### 审查失败自动返工（已实施，2026-11-12）

- 触发：`review` 判 FAIL 且本轮是第 N 次连续审查失败，`N ≤ review.rework_attempts`（默认 1）→ 状态保持 `running`，条件边回到 `implement`；超过上限才 `gate_failed`。
- 反馈注入：取 `REVIEW-agent.md` 的「问题」「建议」与机械门禁失败项，压到 2000 字符，追加到每个 lane 指令尾部「## 上轮审查未通过（必须逐条修正）」；Agent 判 FAIL 却未列问题时使用兜底文案。
