# P2 规划（含差距排入决策）

## 决策记录

- **2026-11-12 用户指示**：把 P1 末审计发现的三项差距排入 P2——① requirements/design 节点未 Agent 化（需求→文档仍靠人写）；② prompt 无模板层（每任务复制改写）；③ `_templates/` 目录不存在（②③ 同源，即 V2.2 规划的模板层未落地）。

## P2 目标

从「单项目可运行」升级为「多项目 + 协议完整 + 需求侧自治」：需求由 Agent 起草、prompt 由模板沉淀、双 Worker 可接管、第二项目按模板接入。

**A2 实际落地（2026-11-12）**

- `requirements_node`：`state.requirement` 原始文本 → `requirements-gen` 模板 → codex → 抽取落盘 `task-XXX/docs/REQUIREMENTS.md`；**空输入不调 Worker**，记 `requirement_input` 门禁失败。
- `design_node`：读 `state.requirements_doc` 全文（不可读则记 `design_input` 失败）→ `design-gen` 模板 → codex → `DESIGN.md`。
  - **设计范围（2026-11-12 核对）**：指技术实现设计，不是原型/视觉 UI 设计。模板只要求三节——`## 文件归属表`（路径 → lane，scope 交集必须为空）、`## 实现策略`（架构选择、约束、lane 串行顺序）、`## 验收映射`（AC → 文件）；不产出线框图、设计稿或交互原型，G2 审批物就是这份 Markdown。含 UI 改动的需求只在实现策略里描述改哪个组件，具体界面由 `fe` lane 在 implement 阶段直接写代码（实例：task b8c4104a 的 `DESIGN.md` 仅 1 行归属表 + 1 段策略）。
- 产物防线（C-008）：`_extract_markdown` 按 `tokens used` / 首个 `# ` / ISO 日志行三重截断；`_doc_gate` 校验 80~50k 字符 + 必需章节（需求：`## 需求`/`## 验收标准`；设计：`## 文件归属表`）。失败 → `gate_failed` + node_run `failed`，条件边直达 END，**不进入 G1/G2 人审**。
- 异常与预算：codex 抛错时收尾 `failed` 防孤儿 running；`start_node_run` 的 PAUSED/低优先级拒发 → `awaiting_human`。
- 追溯：两个文档节点也幂等写 `templates.lock`，node_run 记录 `output_path`。
- 验证：真实 codex 探针（原始需求 → 392 字符合法文档）；AC-02c 13 条断言（空需求 / 垃圾产物 / 日志噪声 / 超长产物）；回归 ac_regression 58 条 PASS=56 SKIP=2、graph_smoke 7/7、smoke_test 20/20。

**B1 实际落地（2026-11-12）**

- **schema**：新增 `workers` 表（id/role/host/pid/status/lease_epoch/lease_expires_at/last_heartbeat_at）；`node_runs` 增 `worker_id / lease_epoch / lease_expires_at / heartbeat_at`。旧库由 `ledger._migrate` 幂等 ALTER 补列；river 库已迁移并核验。
- **租约 API（`platform/ledger.py`）**：`register_worker` / `acquire_lease` / `renew_lease` / `release_lease`。接管在 `BEGIN IMMEDIATE` 内原子完成：存活租约抛 `LeaseHeldError`，过期或同 Worker 可接管；epoch 取全表 MAX+1，接管者严格大于任何旧持有者。
- **栅栏写入**：`finish_node_run(worker_id=, epoch=)` 与 `record_operation(..., lease_epoch=)` 在 epoch 不匹配或节点已结束时抛 `StaleLeaseError` 且**不落库**；旧 epoch 的续租/释放同样被拒。
- **graph 接入**：requirements / design / implement / retro 统一走 `_start_leased_run`（登记 Worker → 领租约 → 生成独立凭据目录），收尾走 `_close`；租约失效时旧 Worker 不再改写任务状态，直接返回失败摘要，交由接管者继续。
- **凭据隔离**：每个 Worker 独立 `projects/river/<task>/workers/<worker_id>/codex-home`，首次从平台基目录复制 `auth.json` / `config.toml`；基目录缺文件时不造空壳，交由 `worker.run_codex` 明确报错（C-007 防线，不静默只读空跑）。
- **看板（B5 随 B1 上线）**：`/api/overview` 新增 `leases` 字段，首页新增「Worker 租约」面板（持有者/角色/host/epoch/心跳/到期/持有状态）。
- **验证**：AC-02e 17 条断言——存活租约不可抢、过期接管 epoch 递增、旧 epoch 收尾/副作用/续租全被拒且未落库、失败路径无残留 running、凭据目录隔离且副本互不影响；回归 `ac_regression` 89 条 PASS=87 FAIL=0 SKIP=2、`graph_smoke` 7/7、`smoke_test` 20/20；常驻看板 `/api/overview` 已返回 `leases`（当前 0 条，尚无绑定租约的执行）。
- **边界（未验证）**：真实双进程接管演练（两个 worker 进程 + 真实 codex 中断）未做；AC-04 仍列在 P1 范围外，首验证据见 AC-02e。

**B2 实际落地（2026-11-12）**

- **schema / 迁移**：`retro_queue` 升级为 outbox——`status` 增 `dead`，新增 `attempts / next_attempt_at / last_error / delivered_at`。SQLite 不能改 CHECK，旧库由 `ledger._rebuild_retro_queue` 重建表并按公共列保留数据（river 6 条 done 原样迁移，二次 `init` 幂等）；索引改在迁移后创建（旧表缺列时 `executescript` 建索引会直接失败）。
- **投递引擎（`platform/memory.py`）**：`deliver()` 先 `attempts+1` 提交再投递（至少一次）；失败记 `last_error` + 指数退避（30s→300s 封顶），`force=True` 立即重放；`attempts >= max_attempts` 转 `dead` 死信；以 AGENTS.md 的 `[id]` 标记去重，崩溃在「已写文件、未标 done」之间时重放会补标 done 且不写第二份。
- **L1 语义**：非 L0 候选不投递，保持 pending 留池人工审核（统计为 `deferred`）。
- **CLI**：`memory.py deliver <db> <project_dir> [--force] [--dry-run] [--max-attempts N]`；`adopt` 保留为 `deliver(force=True)` 兼容入口；`pool` 显示 attempts / next / last_error。
- **看板（B5 随 B2 上线）**：`/api/overview` 新增 `outbox`，首页新增「Retro 投递（outbox）」面板（状态/尝试/下次重试/最近错误/投递时间）。
- **验证**：AC-02f 16 条断言——失败留 pending + 退避、窗口内不自动重放、force 重放、成功后去重、崩溃恢复补标 done、超限转死信且不再投递、L1 留池；回归 ac_regression 110 条 PASS=108 SKIP=2、graph_smoke 7/7、smoke_test 20/20；river 库迁移后看板 `outbox` 显示 6 条历史 done。
- **并发互斥（补验，2026-11-12）**：修复前双进程实测出现重复条目（C-CONC-000 被写 2 次）且 `attempts` 被后写覆盖为 1；改为逐条 `BEGIN IMMEDIATE` 内「复核 + CAS 认领（按 attempts 条件更新）+ 文件读改写 + 标 done」后，120 条双进程并发复测：唯一 120、重复 0、丢失 0、attempts 全 1，竞争方 120 条均 `claimed_by_other`、0 次锁超时。回归固化为 AC-02g（40 条 × 2 进程，5 条断言）。
- **边界（未验证）**：多机 / 共享盘并发投递未验证（跨主机不共享 SQLite 写锁）；磁盘满 / 权限位故障未测；锁等待依赖 sqlite 默认 5s 超时，超时条目计 `locked` 留待下轮。

**B3 实际落地（2026-11-12）**

- **schema**：新增 `lanes` 表（id=`<task_id>:<name>` / node_name / branch / base_branch / file_scope / merge_order / status / merged_at / 时间戳），唯一索引 `(task_id, name)`、顺序索引 `(task_id, merge_order)`。`node_runs.lane` 保留为执行快照，不删列。
- **迁移（`ledger._backfill_lanes`）**：每次 `init_db` 幂等回填——按任务内 lane 首次出现时间定 `merge_order`，同 lane 多次执行取最后一次（状态/分支/file_scope 代表），`base_branch` 串成前驱分支链；已存在的 lane 行不覆盖（避免重启把已完成状态打回）。
- **API（`platform/ledger.py`）**：`register_lanes`（幂等登记计划，`merge_order` 按传入顺序 + `base_branch` 串链）、`set_lane_status`（pending/running/done/failed/skipped，非法值抛 ValueError）、`mark_lane_merged`、`lane_merge_plan`（按顺序返回计划与执行状态）。
- **graph 接入**：实现节点解析 lanes 后立即登记；每 lane 在 `_start_leased_run` 成功后置 running，commit + 收尾成功后置 done（分支重建/空交付/门禁/commit 失败置 failed）；后继 lane 基于前驱分支 `checkout -B` 成功即标记前驱 `merged_at`，末 lane 收尾时标记并入。
- **看板（B5 随 B3 上线）**：`/api/overview` 新增 `lanes`，首页新增「Lane 计划（合并顺序）」面板（任务/lane/顺序/分支/基线/状态/并入时间）。

**B4 实际落地（2026-11-12）**

- **模块**：新增 `platform/maintenance.py`，四项命令统一「先清单、后动作」：`worktrees`（AC-07）、`retry`（AC-08）、`memory-audit` / `memory-rollback`（AC-11）。默认只读，高风险动作（移动目录 / 删除条目）需显式执行。
- **AC-07 孤儿 worktree**：扫描 `<project>/.worktrees`（`--root` 可覆盖）。保留判定叠加五类活跃依据——任务 pending/running/awaiting_human、节点 running/awaiting_human、lane pending/running、存活租约、待审批任务；另保留分支名/lane 名同名目录（`branch.replace('/','-')`）与 24h 宽限期目录。孤儿默认只报告；`--apply` 才移入 `.trash/<时间戳>/`（只移动不删除），`.trash` 超过 `--trash-days`（默认 7 天）且显式 `--purge` 才清理。
- **AC-08 重试分类**：以失败/挂起节点的最新门禁输出为证据，按 V2.2修订 §9.2 分三级——L1 瞬时故障（timeout / 429 / 5xx / rate limit，或未达尝试阈值）→ 同执行器重试；L2 执行器故障（CLI 缺失 / executor 崩溃 / 模型不可用）→ 换执行器；L3 权限/越界/凭据/需求歧义、等待人工或尝试达阈值 → 转人工。任务已 done/cancelled 的历史失败不计入清单；每项附证据片段与建议动作。
- **AC-11 记忆审计与回滚**：解析 AGENTS.md 的 `- [ID]` 条目与续行并核对 retro_queue：`missing_entry`（done 但文件缺失）、`unknown_source`（文件有条目但队列无记录）、`stale_entry`（已 dropped/dead 但条目仍在）、`format`（缺来源/回滚行）、`duplicate`（同 ID 多次）。回滚按 ID 删除条目及续行，队列记录置 `dropped` 并写 `last_error=rollback <id> by <actor> at <utc>`；人工条目无队列记录时补一条 dropped 留痕；重复回滚拒绝。
- **验证**：AC-07/08/11 共 19 条断言全 PASS；全量回归 `ac_regression` 137 条 PASS=135 FAIL=0 SKIP=2、`graph_smoke` 7/7、`smoke_test` 20/20。
- **river 只读审计证据**：`worktrees` 报告根目录 `projects/river/.worktrees` 不存在（当前未使用 git worktree，0 孤儿）；`retry` 输出 3 项 L1（1 项 `gate_failed` + 2 项 `failed` 任务的节点），0 项 L2/L3；`memory-audit` 发现 4 条 `missing_entry`（C-003～C-006 队列 done 但 `projects/river/AGENTS.md` 仅有 C-001/C-002），属历史投递与文件状态漂移，按「只出清单」原则未自动回写，留待人工确认。
- **边界（未验证）**：worktree 目录名只覆盖 `branch.replace('/','-')` 与 lane 名约定；跨盘/符号链接未测；重试分类为关键字规则，未接执行器真实错误码；记忆审计只核对单个 AGENTS.md（`--file` 可指定），不递归子目录；`memory-rollback` 无二次确认，建议先跑审计再回滚。
