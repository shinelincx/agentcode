# V2.2 修订

V2.2 基于用户指令生成：按 [[wiki/V2.1评审]] 的 F1～F8 建议重新修订方案，并特别要求**模型用量不预占、只在事后记录用量**。交付物：[multi-agent-scheme-v2.2.html](../../multi-agent-scheme-v2.2/multi-agent-scheme-v2.2.html)。本页为提案，采纳以评审与 Issue/ADR 记录为准。

## 预算决策记录（用户决策）

- **决策（2026-11-11，用户指令）**：放弃调用前预占，采用事后计量，追求灵活性。
- **性质**：偏好 + 权衡决策。放弃调用级防透支，换取：不阻塞任何 LLM 调用；订阅登录模式原生兼容（无调用前金额接口也能运行）；计量故障不传染主流程。
- **对冲**：超支有界性——最坏越限 ≤ 在途任务数 N × 单任务上限 U，二者为可配置可审计参数（初始值按角色历史 P95 × 2，每周校准）。
- **诚实声明**：该模型不保证「用量绝不超过配额」，只保证「超过部分 ≤ N×U」。若出现零超支硬约束场景，可回退 V2.1 预占模型——两版共享 cost_ledger 与状态机，可按项目切换。
- 该决策同时消解了 F1（V2.1 预占模型在订阅模式下无执行点的阻塞问题）。

## P1 前置修订：kill 语义（2026-11-11，源于 AC-02 发现 B）

依据 [[wiki/P0a确认]] 发现 B（codex 执行器存在 supervisor 进程自愈：kill worker 进程树后约 50 秒被 codex-code-mode-host 自动重启续跑），修订本方案 §9.2 与 §8.4 如下：

**修订 1 · §9.2 重试分级的假设修正**
- 原 L1「同执行器 attempt 重跑」→ **由执行器 supervisor 自动完成**（自愈即免费 L1）。编排器职责从「拉起重跑」变为「检测自愈结果」（node_run 出现新进程产出即视为 L1 生效），超时未见自愈才介入。
- L2（换执行器）、L3（人工挂起）不变。
- 新增**停止意图两级**：「软停」= kill worker 进程树（允许自愈，适用瞬时故障）；「硬停」= 编排器主动终止（适用用户取消 / 预算 PAUSED / 安全事件）——硬停不可依赖进程 kill（会触发自愈复活），须终止 supervisor 或会话级取消。

**修订 2 · §8.4 PAUSED「在途跑完」的实现修正**
- 原设想依赖进程管理（新节点不启动、在途跑完）。修正为**门禁层拒发**：PAUSED = 不创建新 node_run + 产物验收拒收（账本状态机判定），进程层无需 kill——在途节点被 kill 后的自愈恰好与「跑完」语义兼容，跑完后因无新 node_run 而自然停住。

**待验证项（P0b/P1 Week 1 实验补充，当前为单次观察的推断）**
1. supervisor 自愈的边界：重启次数上限？何种 kill 不触发自愈？优雅退出（Ctrl+C 语义/SIGTERM 等价物）是否绕过自愈？
2. 硬停实现候选：(a) 终止 codex-code-mode-host（影响用户桌面会话，需隔离评估）；(b) 会话级取消接口；(c) 独立 CODEX_HOME 隔离 Worker。
3. claude 执行器是否同样存在自愈（对称性未验证）。
