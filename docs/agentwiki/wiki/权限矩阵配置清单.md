# 权限矩阵配置清单

## 结论

事实：V2.2 §6.4 的「8 角色 × 项目仓库/共享资产/数据库/staging/生产/CI-CD + 实现层」矩阵已逐格对照当前平台配置（`platform/`、`projects/*/project.yaml`、`.github/workflows/`、`.gitleaks.toml`），建立一一映射（见下表）。整体结论是**部分一致**：结构性红线（生产不可写）成立；「沙箱只读」（G-01）与「lane 写入前置限制」（G-02）已于同日整改（见「整改记录」），矩阵外角色 review 亦统一为只读；「CI token 白名单」已整改（显式 `permissions: contents: read`），仅「DB 账户隔离」仍未落地，当前由提示词约束 + 编排层门禁替代。

本页是 C2「权限矩阵复查」的交付物，验收标准为「清单与实际配置一一对应」。G-01（文档节点只读）、G-02（lane 根 cwd 写入前置限制）与 G-03（CI 最小权限）已于同日整改并补回归断言；G-04~G-06 **尚未整改**，是否实施需另行确认（见后文）。

### 逐项差异说明

- **需求/设计/Retro 的「只读」已整改（G-01，2026-11-13）**：三个文档类节点改为 `sandbox="read-only"`（[graph.py](../../../platform/graph.py) 第 321 行附近），并新增第二层守卫 `_repo_dirty()`（同文件 `_out_of_scope` 之后）：节点执行前后各自取 `git status --porcelain`，新增脏文件即 `doc_repo_clean` FAIL、`gate_failed`，不进 G1/G2。文档产物仍由编排层写任务目录（仓库外），正常路径不触碰仓库。回归覆盖：`ac_regression` AC-02c 场景 6（断言 `sandbox=read-only` 且守卫留痕 PASS）与场景 7（模拟脏文件 → 不进入 G1、终态 `gate_failed`）。
- **lane 写入前置限制已整改（G-02，2026-11-13）**：先证伪原方案——实测 `codex-cli 0.167.1` 在 `-s workspace-write -c 'sandbox_workspace_write.writable_roots=[]'` 下仍可写 cwd 子目录，`writable_roots` 是增量授权而非限制（工作区探针 `b/probe.txt` 被创建）。改用 cwd 隔离：模板渲染的 lane 由 `_lane_workdir()` 推导唯一顶层目录并作为 codex cwd（workspace-write 下 cwd 即可写范围），写入因此被限制在 lane 子树；同时新增 `lane_workdir_prefix` 守卫，拦截「cwd 已是 lane 根却写 repo 相对路径」产生的 `prefix/prefix/` 嵌套（该路径仍匹配 lane scope，事后 scope 门禁不会发现）。事后 `_out_of_scope` 保留为第二层。回退场景：多根 scope、含通配顶层、目录不存在、以及逃生口 `lane.prompt`（假定仓库根）均回退仓库根，仍只靠事后门禁。
- **测试/部署命令在编排层以宿主权限运行**：这是已记录的设计权衡（`projects/river/AGENTS.md` C-001：codex 沙箱内 vitest 因 esbuild EPERM 无法运行），因此 test/deploy 节点 `with_codex_home=False` 且不进入 codex 沙箱。矩阵中「测试目录写」「测试库只读」「staging 只读」均无对应配置；当前 staging 部署命令具备宿主机 docker 全权。
- **CI/CD**：仓库 CI 只跑零 token 的模板/回归/冒烟与 gitleaks；workflow 未声明 `permissions`，使用默认 `GITHUB_TOKEN` 权限，不是矩阵要求的「token 白名单」。部署不经过 CI，走本地 WSL `docker compose`，因此「部署触发 build/deploy-staging」在实现上落在 deploy 节点命令。
- **记忆文件**：代码中 AGENTS.md 的唯一写入路径是 `platform/memory.py` 的 `deliver/adopt`（CLI 触发），retro 节点只生成 `RETRO.md`（`graph.py:1541`），不直接写 AGENTS.md。矩阵「唯一写入者是 Retro 节点」在实现上拆成「Retro 生成报告 + 独立记忆 CLI 落盘」，写入方仍唯一，但不由节点内自动完成。
- **共享资产**：river 与 pdca-erp 均无 `_contracts`/`_ds` 目录，也无消费方，故架构角色的 PR 权、原型的 `_ds` 只读目前无适用对象；一旦引入共享资产，需新增仓库 ACL 与 PR 门禁。

## 冲突与未知

- G-02 回退面：多根 lane scope、含通配顶层、目录不存在、逃生口 `lane.prompt` 均回退仓库根，这些场景仍只靠事后 `_out_of_scope`；`ac_regression` 的 MULTI-01 使用逃生口 lane，因此未覆盖 cwd=lane 根的真实实现链路，仅由 LANE-01 纯函数断言覆盖推导与守卫。
- AC-06「沙箱越界矩阵」仍为手工 SKIP（`ac_regression.py:1101–1102`），结论来自 `P0a确认.md` 的历史手工记录（越界写/父目录写 BLOCKED），未在 CI 中自动复验；矩阵「实现层」列的 OS 级结论主要依据该次手工验证。
- 网络出站策略：平台无 OS 层网络白名单（V2.1 评审已记录该防线退化为提示词 + 审计），本清单未将其计入矩阵缺口，因其不在 §6.4 矩阵列内，但属同一风险面。
- proj-b 复用 river 的 `codex-home` 作为只读凭据源（`projects/proj-b/project.yaml:16`），每个 Worker 仍独立复制，未产生第二份长期凭据副本；这一点与「Worker 零长期凭据」的差距沿用 P1 结论。
- 本页状态为 draft：矩阵到配置的映射与 G-01/G-02 整改由 Agent 核对代码得出，尚未经人工复核签字。
