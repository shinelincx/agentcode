# 角色配置管理（控制台 · project.yaml）

## 决策

用户 2026-11-12 指示：把各角色的配置功能加入管理控制台。实现遵循「配置单一事实源 = `projects/<proj>/project.yaml`」：控制台只对**已存在**的配置项做定点替换，不新建节点、不整文件重写，中文注释与缩进原样保留；保存前整体校验，失败 400 且不落盘；成功后追加审计并刷新运行时，无需重启进程。

## 逐 Agent 独立模型配置（2026-11-13，本次实施范围）

用户反馈：方案要求各 Agent 的模型独立配置，但设置页只有全局默认、降级模型和强角色列表，要求优化。方案依据为 V2.0 §7 的「角色级模型路由」以及 V2.2 §8.4 的降级语义；改造前代码事实是所有正常调用都只取 `model.default`，页面与运行时均未提供角色覆盖。

本次已实施（用户上述反馈为需求授权）：

- 在既有 `model` 段增加 `roles.<role>` 叶节点，角色集合沿用 `KNOWN_ROLES`；NORMAL/ALERT 下优先使用角色模型，缺失时继承 `model.default`，因此旧配置仍可运行。
- DEGRADED 下，非 `strong_roles` 仍统一使用 `model.degraded`；强角色使用自己的 `model.roles.<role>`（未配置才回退默认），不削弱既有预算降级策略。
- 设置页拆分「全局路由策略」与「Agent 独立模型」，逐角色显示中文职责和配置项。`test`、`deploy` 当前是确定性命令节点，不调用 LLM；页面保留其角色配置并明确标注现状，不宣称这些值会改变当前节点行为。
- 两个真实项目的 YAML 已补齐角色叶节点，初始值均沿用原默认模型，功能改造本身不改变项目模型行为；控制台仍只修改既有节点，不放开任意配置创建。旧项目未声明某角色时，页面显示默认继承值的只读字段，需先在 YAML 声明该节点才能独立编辑。
- 回归已覆盖配置校验、注释保留、HTTP 保存、默认回退、角色覆盖、强/弱角色降级，以及图执行中各模型调用与账本的实际角色值；使用 stub codex，不消耗真实模型额度。

未知与边界：独立模型只决定下一次节点调用的路由，不回溯修改挂起前已完成的调用；真实供应方是否支持用户填写的模型名不在本仓库校验范围内。

## 写入机制

`platform/config_store.py`：

- `load(path)`：PyYAML 读取；解析失败抛 `ConfigError`。
- `validate(config)`：返回错误列表；只校验出现的字段（缺省由运行时回退默认值）。
- `apply_updates(path, updates, actor)`：dotted path → 新值；跳过未变化项；合并后整体校验；用 `yaml.compose()` 的节点 mark 定点替换标量 / 流式序列 / 块序列；未知键、缺失节点、映射叶直接拒绝；写临时文件后 `os.replace` 原子替换；变更追加 `<workspace>/config-audit.jsonl`。

实现细节：

- 块序列的 `end_mark` 落在下一 token 前（含换行与缩进），替换前回退空白，避免吞掉下一行（首版实测把 `healthcheck:` 拼到上一行，已修）。
- 字符串统一单引号转义（`'` → `''`），拒绝多行字符串；空列表渲染为 `[]`。
- 替换区间重叠直接报错，不做部分写入。

## 控制台端点

| 路径 | 方法 | 行为 |
| --- | --- | --- |
| `/config` | GET | 配置页；只读模式表单禁用，控制台模式可保存 |
| `/api/config` | GET | `{file, config, editable, meta, audit}`；meta 含角色 / 执行器 / 审批闸门 / 门禁命令 |
| `/api/config` | POST | 仅 `--control`；需 `X-Control: 1` + Origin 白名单；`{updates, by}`；校验失败 400、未开启 404、越权 403 |

页面按分区渲染执行器、全局模型策略、8 个 Agent 独立模型、预算、测试门禁、部署 staging、审批闸门与项目路径，一次保存只提交变化项；页头常驻「配置」入口，每次保存后重载当前值并展示最近审计。角色字段以 `model.roles.<role>` dotted path 提交，复用通用收集与保存逻辑。

## 限制与未验证

- 只支持编辑既有标量 / 序列节点；新增配置块仍须手工改 YAML。
- 不校验模型名是否存在（模型清单不在本仓库事实源内）。
- `gates` 的 approver / SLA 仅登记与展示，审批放行仍由图内 interrupt 决定。
- `max_inflight_tasks` 仅登记，执行仍为单队列串行。
- 无鉴权，依赖 `127.0.0.1`；同一 YAML 的跨进程并发写未加锁（控制台按单实例写入）。
