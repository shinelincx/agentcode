# Prompt 模板评审与修复（2026-11-16）

## 决策

用户要求分析 7 个 Prompt 模板并提出优化建议，随后授权修复复核表中的五组问题。以下保留历史评审与证据，当前状态见「修复结果与验收」。后续修改模板时按 SemVer 更新受影响模板与 manifest，同步黄金用例并运行专项回归。

## 评审范围与依据

- 7 个模板：requirements-gen 1.4.0、design-gen 1.2.0、prototype-gen 1.1.0、implement-lane 1.2.0、gate-fix 1.2.0、review-diff 1.2.1、retro-gen 1.2.0。
- 渲染层 [templates.py](../../../platform/templates.py)：required 参数缺失抛 KeyError、optional 缺省、列表 join、`templates.lock` 哈希快照与漂移检测。
- 消费方门禁：`graph.py` 的 `_doc_gate`（必需标题）、`_lanes_from_design`（归属表/lane 解析）、`_ac_coverage`（AC 全覆盖）、review 结论 `PASS/FAIL` 解析。
- 黄金用例：`_templates/evals/golden.yaml` 17 例（渲染层断言；`--live` 产出断言未建立基线）。
- token 成本（prompt_eval 实测）：requirements ~723、design ~564、prototype ~430、implement ~355、gate-fix ~318、review ~580、retro ~430。

## 总体评价

结构统一（六段式）、输出契约基本可机检、治理机制（SemVer + lock 哈希 + 漂移检测 + 黄金用例）健全。主要缺口集中在：信息注入不完整（原型看不到参考图、复审看不到上轮结论）、个别硬约束未闭环（lane 值域、实现阶段弱化测试）、产出语言未声明。

## 复核与优先顺序（2026-11-16）

以当前工作区的编排代码与 manifest 1.4.0 为依据。七个模板文件、参数清单与黄金用例相对 `3ffd905` 无变更。以下仍是提案，实际复跑仅使用本地渲染、临时 SQLite、桩 Worker 和纯函数样例。

| 顺序 | 涉及模板 | 事实与证据 | 优化建议 |
| --- | --- | --- | --- |
| P1 · 1 | `review-diff` | 模板要求「结论」以大写状态开头，审查节点却取章节里第一个 PASS/FAIL，不校验 Worker 退出结果。桩输出先提到 PASS、最终结论为 FAIL，实际 `review_agent` 门禁记成通过 | 将状态固定为「结论」的首个非空行且独占一行，理由放后面。按格式严格校验，拒绝不完整或矛盾结论。增加普通 PASS、FAIL、模糊文本、执行失败的图回归，然后再统一 severity |
| P1 · 2 | `design-gen`、`requirements-gen` | 交换文件归属表列序后，原型识别出 fe，实现却把路径当成 lane。验收映射写「缺少 AC-1」，当前 `_ac_coverage` 仍通过。旧 F-1 将实现端描述为「不识别别名」，复核确认它会按别名原文建立 lane | 统一按表头解析并规范化 lane，在进入 G2 前校验空范围和实际 AC 映射。需求 AC 从明确列项提取，小型任务可只保留一条可验收标准 |
| P1 · 3 | `implement-lane`、`gate-fix` | 门禁修正前检查文件范围，修正完成后直接进入 Git 暂存。实现模板缺少保留测试约束，修正模板的 attempt 来自节点历史计数，在同一修正循环里不代表第几次修正 | 两个模板都把测试作为交付约束，分别传入允许修改的范围和当前改动文件。显示当前门禁第几轮与总轮数，提交前对最终变更再次验证范围 |

### 工程改进提案

1. **保留一个独立交付判定入口。** 先落实专项方案，将固定提交、批准版本、当前门禁、取证缺口和最终去向作为节点的接口。实现阶段提前做本 lane 检查，同时输出可供校验的交付证据。Git 与账本核对集中在 `review` 消费证据的入口，模型只处理尚需独立判断的行为。交付后执行的验证由 `test` 负责，staging 和 G3 负责验收部署结果。机械取证失败先补证据或交人工，有证据的缺陷才进入代码返工。低风险跳过模型的路径仍写出判定理由，并可按需避免准备 Codex 凭据。[编排](../../../platform/graph.py) · [[wiki/Prompt模板#review-diff 1.3.0 专项评审与优化提案（2026-11-16）]]

3. **减少同一工作的反复执行。** 结构化意见经校验后只交给负责 lane，保留既有交付，按依赖重验后续 lane。优先复用同一提交或等价树、同一门禁定义及配置、同一环境和覆盖范围的结果。跨 lane 最终验证、额外 `coverage`、不同环境或与作者隔离的验收照常独立执行。先在代表性的干净改动、已知缺陷和证据缺失场景做对照，记录审查额外发现、误拦截、返工触及 lane、模型调用及端到端耗时，再调整哪些任务需要模型审查。[现有图与门禁](../../../platform/graph.py) · [[wiki/Prompt模板#review-diff 1.3.0 专项评审与优化提案（2026-11-16）]]
