# V2.1 评审

评审对象：[[wiki/方案演进]]（V2.1.0，2026-11-11）。评审依据：V2.1 全文、[[sources/V2.1技术核验]] 的一手资料核验、V2.0 原文（本轮已全文阅读）。本页为评审结论，属提案性质；方案正式采纳仍需 Issue/ADR 记录。

## 总体结论

V2.1 相对 V2.0 是实质性改进：用一手资料纠正了 V2.0 的技术错误，并把「已设计 / 已实现 / 已验证」分开陈述。**有条件通过**：F1（预算执行点）须在 P0 前决策，F2/F3 建议进入 P1 前修订。风险主轴已从「设计缺口」转移到「交付负担」——协议正确但重，缺最小子集分层。

| 技术正确性 | 6.0 | 9.0 | 事实：七项修正均有官方文档出处。 |

## 核验通过的修正（事实）

1. LangGraph 中断恢复从节点起点重执行，中断前副作用须幂等。
2. 多起点 add_edge 是 AND 汇合，V2.0 的成功/失败 OR 路径骨架有误。
3. `^1.2` 接受 minor，V2.0「^ 自动跟随 patch」表述错误。
4. npm 撤包受平台条件限制且不能撤销已安装依赖，不能作日常回滚。
5. inotify 是监听审计，不提供写入前授权裁决。
6. 预算从「调用后记账」升级为「请求前原子预占 + 完成后结算」——修复并发透支缺陷。
7. 业务账本与 LangGraph checkpoint 权责分离。
8. 租约 epoch 处理 Worker 失联接管的双提交问题。
9. Retro 降级为候选经验 + 人工审核，修复记忆污染风险。
10. 弃用「重犯数 ÷ 全部失败数」作学习改善主指标。
11. 单项目 → 双项目 → 四项目渐进替代直接四项目。
12. 新增 AC-01～12 可执行故障验收场景。

## 评审发现

### F1 · P0 阻塞：预算模型缺执行点（高）
第八章预占模型依赖「LLM 调用经可控出口」，但第三章同时声明「不预设 API Key、订阅登录均可透传代理」。若所选执行器（Codex 订阅模式）无法按调用计量，预占模型对主要成本驱动无执行点；方案将其列为 P0 验证项但未定义失败后的备选。
**建议**：P0 必须二选一——(a) 试点仅用 API-key 计量模式；(b) 订阅模式以调用次数/任务数上限替代金额预占，账本记次数。不允许「验证失败再想办法」。

### F2 · 高：P1 协议面过载
第四章 10 类记录 + 租约 + outbox + 幂等键 + 审批哈希，全部隐含在 Week 1–2 建成并通过 8 个 AC 场景。已声明「实现时可按事务合并存储」，但未定义 P1 最小子集。
**建议**：明确 P1 子集——tasks / node_runs / operations / approvals / budget_accounts 为必须；单机单 Worker 串行下，outbox 可简化为同步 Retro 失败重试队列，双 Worker 接管可降级为「崩溃 → attempt 重跑」；完整租约与 outbox 在 P2 引入。

### F3 · 高：学习闭环价值兑现推迟
第十章「候选不自动注入 system prompt、审核后受控采用」修复了污染风险，但 G1 原始诉求（Agent 越做越好）现在完全依赖人工审核速度；未定义审核 SLA、积压处理与审核人。七周窗口内可能只产出候选、零采用。
**建议**：增加低风险自动层——项目内、非权限、非生产、格式/工具调用级候选允许自动采纳（带审计 + 一键回滚 + 每月抽查）；跨项目、权限、架构级保留人工审核。

### F4 · 中：P0 任务清单过载
P0（3–4 天）需验证认证、计量、沙箱越界（AC-06 级）、执行器启停、审批人登记。沙箱越界矩阵本身接近一个小测试工程。
**建议**：拆两级——P0a（3–4 天）：认证 + 计量 + 启停 + 审批人（决定 F1 走向）；P0b（并入 P1 Week 1）：完整沙箱越界矩阵。

### F5 · 中：权限具体性回退
V2.0 的 7 角色 × 7 资源矩阵被替换为权限原则列。V2.1 框架（硬限制 + 审计）更诚实，但 P0 后配置沙箱/ACL 需要具体输入。
**建议**：P0 确定 OS 后，按 V2.1 原则把矩阵重制为具体配置清单（挂载点、ACL、网络策略）。

### F6 · 中：AC 场景缺可复用 harness
12 个场景需进程注入、预算并发竞争、断流等操作，手工执行成本高且难重复。
**建议**：AC-01～06 至少脚本化，P1 建成即固化为回归测试，各阶段重跑。

### F7 · 低：宿主与目标 OS 机制差异未列清单
已正确声明 Windows 仓库不代表 Linux inotify 配方可用，但差异影响面（inotify ↔ ReadDirectoryChangesW、worktree 行为、符号链接语义、文件锁）未列出。
**建议**：P0 定 OS 后补机制差异对照表。

### F8 · 低：secrets 存储与轮换未定义
副作用执行模块持有 PR/合并/部署凭据，租约接管要求撤销或隔离，但凭据存储位置与轮换机制未提。
**建议**：并入 P0 认证确认项。
