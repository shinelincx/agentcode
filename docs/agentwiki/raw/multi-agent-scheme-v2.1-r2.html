02

目标、范围与交付定义

目标是在明确的预算、权限和验收约束下，将需求推进到可追溯的 staging 交付；失败后可以恢复或交还人工，并避免重复执行未经确认的外部操作。

一次成功交付应具备需求与验收标准版本、实现 commit、独立检查结果、适用审批、部署制品摘要及冒烟证据。生成代码或创建 PR 不等于交付成功。人工审批允许存在；“无人工代写代码”作为单独的自动化维度统计。

范围 首版处理
单项目闭环 优先选择小型、可恢复、有稳定验收的真实任务。
四项目并行 双项目依赖与隔离验证后扩展；公共控制模块故障另行定义影响。
生产发布 Agent 无生产写凭据，由获授权人员触发受保护 CI。
自动学习 首版收集候选并人工确认，不以自动写入条数作为交付条件。
多机队列与复杂看板 吞吐、可靠性和排障需求明确后再引入。

V2.0 中 60%/85% 跑通率、10 分钟回滚、月预算偏差 10% 等数值作为历史目标候选保留，不在缺少样本和演练时承诺。预算准入与审批有效性是必须成立的约束；性能、成功率和恢复时长由试点校准。

03

总体架构与技术取舍

三层组织与最小链路

模板层保存角色指令、门禁配方和版本配置；项目层保存独立代码、工作区与状态；平台层负责调度、预算、副作用执行及观测。共享资产以不可变版本引用，通过升级 PR 接入。

需求与验收 → 计划/风险分级 → 必要人审 → 按需执行 → 独立验证
                                              ↓ 失败回修（有上限）
具体制品审批 → staging 部署与冒烟 → 持久化任务终态
                                      └→ 待处理事件 → 异步 Retro → 候选经验

派发、调用、结果提交：检查任务版本、租约、权限、预算
模块 对外职责 内部承担的复杂性
Orchestrator 提交、推进、暂停、取消、恢复任务 生命周期、人审、业务账本与图状态协调。
Worker 适配器 接收任务包，返回结果和制品清单 执行器协议、隔离、进程、取消与用量。
预算模块 预占、结算、对账 全局/项目/任务账户和在途费用。
副作用执行模块 执行已授权的 PR、合并、部署等操作 幂等、租约、外部结果核对及审计。
验证与发布 检查并发布具体制品 可信 CI、证据、候选版本和兼容性。

首版可在一个代码库中实现上述模块，不要求拆成独立微服务。只有实际存在不同执行器时才抽取必要差异，避免仅转发参数的多层接口。

选型与升级条件

领域 首版提案 验证与升级条件
编排 保留 LangGraph，锁定实际依赖版本 验证中断、重启、并发合并、异常路径；骨架不作为已运行实现。
执行器 先验证一种，Codex 为候选；Claude Code 后续评估 实测认证、权限、调用统计、取消、恢复和工具协议后才启用替换。
状态/队列 单机 SQLite + 持久化任务记录，进程内信号仅唤醒 WAL 不替代业务领取、租约、重试和备份；实测写争用及重启。
数据库升级 测量后评估 Postgres 多机协调、可用性或写争用触发；准备迁移脚本、核对与切换演练，不承诺只换连接串。

04

任务协议、状态与数据责任

Worker 输入与输出

输入包含 task_id、revision、node_id、attempt_id、lane_id、lease_epoch、到期时间、base_commit、允许改动范围、验收引用、上下文清单、有效权限、预算限额和配置摘要。输入文件以哈希绑定，不依赖隐含共享对话。

输出包含成功/失败/阻塞/取消结果、错误分类、产物及哈希、实现 commit、检查记录和用量。Worker 自报成功须经编排器核验租约、版本和门禁才能接受。

状态权威与一致性

业务执行账本是任务生命周期与授权的权威，由 Orchestrator 受控转换；LangGraph checkpoint 保存内部图进度，不单独证明业务操作已完成。Dashboard 仅作查询视图。

queued → running → awaiting_human → running → succeeded
              ├→ paused_budget / paused_dependency → running
              ├→ needs_reconciliation → running / needs_attention
              ├→ needs_attention → running / failed
              └→ cancelling → cancelled

succeeded、failed、cancelled 为任务终态。重开终态任务建立显式新修订或运行。恢复时先核对账本、有效租约、任务版本和外部结果，再恢复图；不假设 checkpoint 与业务账本具有跨系统原子事务。节点重放读取已完成操作记录，不重做相同副作用。

必要逻辑记录

下表定义数据责任，非已执行 DDL；实现时可按事务和查询需要合并存储。

记录 必要信息及约束
tasks project/task、revision、status、state_version、deadline、风险级别；版本条件更新。
node_runs task/revision/node、attempt、输入摘要、lease_epoch、状态、错误和时间；一个逻辑节点同一时刻只有一个有效租约。
lanes branch、base_commit、目录、scope、环境命名空间、租约与保留原因；不得仅靠 active 判断清理。
artifacts 生产任务/attempt、commit、内容哈希、位置、验收状态与配置清单引用。
operations 唯一 operation_key、授权载荷哈希、外部 operation_id、intent/succeeded/unknown/failed。
approvals 任务修订、制品/发布清单哈希、审批人、决定、理由、有效期及权限依据。
gate_results 标准 ID、目标 commit/哈希、配方版本、结果及可信报告链接；保留历史。
budget_accounts 作用域、周期、币种、上限、已结算/预占金额、版本；同一事务核验所有适用账户。
reservations/cost_ledger request_id、attempt、模型与计价版本、预占/实际费用、供应方请求标识、对账状态；回执幂等。
outbox/memory_candidates 唯一终态事件与消费状态；候选来源、适用范围、版本、审核和撤销记录。

金额用统一精度的整数最小计价单位或固定精度十进制，不以浮点累加控制预算。全局预算由单一权威账本控制，不由四份项目库临时汇总后分别放行。日志脱敏、限制留存；大日志可存制品库，数据库保留引用和摘要。

修订和失效传播

需求、契约、实现 commit 或门禁配方变化时生成新的 revision/输入摘要，标记受影响下游结果和审批失效。审批不只绑定路径；新提交需重新评估必要门禁。任务与节点分别设重试次数、累计费用和墙钟时长上限。

05

可靠执行、恢复与清理

幂等与结果不确定窗口

operation_key 标识一次逻辑操作，由任务修订、节点、操作类型及批准载荷摘要生成。同一操作重试沿用该键；每次变化的 attempt_id 不能作为唯一幂等依据。

1. 核验租约、任务修订、审批哈希和预算许可。
2. 原子写入操作意图；相同键已成功 → 返回既有结果。
3. 调用支持幂等键的接口，关联外部 operation_id。
4. 保存结果再推进节点；任务终态和 outbox 事件同事务提交。
5. 崩溃/响应丢失 → 先查询外部结果，再补记或安全重试。
6. 接口不支持幂等且结果不可查询 → needs_reconciliation，禁止盲重试。

这是至少一次调度下对特定副作用的去重和核对，不承诺任意系统的 exactly-once。PR、合并、部署和发布凭据由受控副作用模块持有，Worker 不得绕过授权检查直接执行。

Worker 失联和接管

心跳与业务进度分开观测。超时标记 suspect，暂停接受旧 epoch 结果；确认停止或隔离旧进程后重派，接管时原子递增 lease_epoch。结果提交和副作用端都校验 epoch。旧进程不能停止时，新 attempt 使用独立工作区，旧产物禁止合并；数据库、凭据等也需撤销或隔离，不能只在数据库中改租约字段。

心跳和超时按工具最长调用、负载及网络实测配置，不将失联直接判为死亡，也不因连续两次失败就假定执行器不合适。

错误 恢复策略
临时网络错误且无不确定副作用 有上限的指数退避与抖动，计入总费用。
门禁失败 附证据回修；达到修复次数/费用/时间上限后交人工。
权限拒绝 检查范围或配置，needs_attention；不自动扩权重试。
预算不足 paused_budget；恢复前重新校验版本、租约和准入。
副作用结果未知 needs_reconciliation，查询或人工核对。
执行器故障 回收旧实例、保全产物，验证备用能力与上下文迁移后重派。

LangGraph 落地约束

中断恢复会重执行所在节点，因此中断前副作用仍须幂等。多起点 add_edge 是等待全部起点完成，不是成功/失败任一入口。中断文档、StateGraph 源码

显式定义错误分类、终态路径及稳定 thread_id；不使用未定义的错误节点，不以宽泛捕获吞掉人工中断。按锁定版本管理 checkpointer 生命周期。并行 artifacts 定义合并规则或拆为角色独立字段，测试冲突键与失败分支。Graph API

本版用协议和验收场景替代未验证的框架代码；可运行样例须附依赖锁文件、启动方式及恢复测试。

清理和备份

清理同时核对终态、租约、未结操作、保留标记及归档。人审等待、预算暂停、失败保全和对账任务不算孤儿。删除前校验绝对路径在授权目录内，确认没有活跃进程和未保存产物。

先归档提交/差异和必要日志，再通过 Git 工作区管理命令处理 worktree；隔离区设置保留期和恢复入口。数据库与制品联合备份并演练恢复，checkpoint 存在不能证明磁盘故障后的可恢复性。

06

角色、lane 和运行隔离

职责按需启用

职责 触发与产出 权限原则
需求 验收不完整或需求变化；明确标准和未知项 读资料，写指定需求文档。
架构 跨模块、契约、迁移或高风险；计划、依赖、归属表 可提契约变更 PR，不直接发布共享资产。
原型/UI 界面变化需验证；原型及设计说明 读设计资产，写专属原型目录。
前端/后端 按依赖图实现 仅写授权范围，使用隔离环境。
测试/审查 独立验证候选制品 可写测试目录和临时数据，不能改受保护门禁或批准自己的实现。
部署 CI 构建/部署/冒烟，Agent 准备输入或诊断 仅允许的 staging 操作，无生产写凭据。
Retro 后台工作 终态后提炼候选经验 读脱敏证据，写候选区，不直接改人工规则。

执行器差异是可评测手段，独立审查主要依靠隔离上下文、可信验收及权限。小型后端任务可以跳过 UI；低风险任务可依据已有批准策略简化审批。

lane 与资源范围

lane 是受租约管理的执行通道，包含分支、独立 worktree、Worker 和环境命名空间，可包含多次可追溯 attempt。并发前检查规范化路径与逻辑依赖；共享 migration、锁文件、路由和公共类型以显式串行任务处理。

路径校验考虑大小写、父目录、重命名及符号链接。隔离范围还包括数据库/schema、账号/测试数据、端口、缓存、临时目录和 staging；共享资源声明独占或限额。合并由受控入口串行推进，后合并者对最新目标分支候选重新执行必要检查，结果绑定具体 commit。

硬限制与审计

由目标 OS 沙箱、容器挂载/ACL 等限制真实访问；分别控制 MCP 工具、shell、网络、凭据和 Git 元数据。只有 MCP Server 清单不能阻止命令行或直接网络绕过。

inotify 负责监听审计，不承担写入前的授权裁决。inotify 文档 workspace-write 名称不证明任意 file_scope 已被硬执行；Codex writable_roots 为额外可写根目录，实际权限需按版本验证。配置参考

目标 Worker OS 在 P0 确定。仓库位于 Windows 不意味着 Linux inotify 配方可直接使用；验证在实际环境覆盖越界写、凭据读取、共享资产直推及网络出口。

07

人工闸门和质量验收

审批绑定制品

按项目设置低/中/高风险规则，由受控策略分类。Agent 可提出风险升级，不能自行降低等级。生产、扩权、破坏性迁移及不兼容跨项目变更始终进入明确审批；其他操作可复用已有授权，不反复询问同一许可。

审批记录责任人、备份责任人、时效、revision/commit/发布清单哈希、范围及到期时间。只有明确且有效的 approve 放行；缺失、异常或未授权响应维持等待。制品变更使对应审批失效；超时按工作时段和项目策略升级通知。

分层门禁

层次 检验问题 证据
需求 输入、预期结果、范围和未知项明确吗？ 版本化标准及澄清记录。
静态 类型、依赖、敏感信息、改动范围合规吗？ 可信 CI 报告和配方版本。
行为 正常、异常、权限、回归路径符合要求吗？ 可执行测试及制品绑定结果。
集成 提供方与消费者组合兼容吗？ 对候选版本的消费者回归。
交付 部署与批准内容一致并可用吗？ 镜像摘要、部署记录、冒烟报告。

章节齐全、无 TBD、测试引用全部需求编号只能检查形式完整性，不能证明正确。保留真实未知项及责任人，不为通过门禁而删除问题。LLM 提示歧义不能替代独立验收。

前端优先复用设计系统，允许必要原生语义元素、布局和经说明的新组件；重复实现已有能力需说明，新组件走贡献流程。测试允许受控建数与清理，并按命名空间隔离。覆盖率区分行/分支、增量和项目风险，不能统一以 80% 判定质量。migration 验证升级、兼容和声明的恢复路径，不强制假定每次 down 都安全。

08

预算准入、结算与暂停

预算不变量

对全局、项目、任务所有适用账户：
已结算金额 + 在途预占金额 + 本次调用费用上界 ≤ 有效额度

单一权威账本事务检查并预占所有适用账户。币种和计价精度统一，周期时区固定配置（默认 Asia/Singapore）；日、月、任务额度分别控制，日重置不能绕过月上限。

预占覆盖输入、最大输出、模型计价和可计费工具等；多轮 Agent 逐次准入，另设任务总费用/调用数。无法取得可信费用上界的模式需设置保守限额并说明保证范围，不宣称严格预算可控。供应方账单为最终对账依据，认证和收费模式在 P0 验证。

阶段 行为
准入 从可信身份确定项目与角色，原子预占；不只依赖 Worker 自报标签。
执行 唯一 request_id，限制输出、超时、并发和计费工具；流式连接断开不等于调用停止。
结算 按实际用量和价格版本扣账并释放差额，重复回执幂等。
不确定 响应丢失/取消未确认时保留预占并对账，不按超时直接释放。
核对 查询供应方结果或人工处理，保留误差及调整依据。

首版固定项目上限，受控调整；共享池借用仍受全局硬限额。跨周期在途请求按明确规则归属，不跨日自动清零。账本不可用时拒绝新付费调用；保留已执行状态及非 LLM 的停止、安全恢复能力。

状态与动作

状态 初始建议触发线 动作和恢复
NORMAL 结算 + 预占低于告警线 按路由和配额运行。
ALERT ≥80%，试点校准 告警、限制低优先级新任务；周期重置、额度追加或预占释放后按滞回规则恢复。
DEGRADED ≥90%，试点校准 仅在能力兼容且通过评测时降级后续调用，暂停非必要 Retro。
CIRCUIT_OPEN 无法满足预占硬限额或策略主动关闭 返回明确预算拒绝原因，paused_budget；额度恢复后重新准入，不作网络错误盲重试。

累计支出本身不假定下降。项目额度不足只暂停该作用域，全局不足才全局限流。运行中请求只能在有效预占内继续，取消不承诺立即消除费用；任务在可验证检查点恢复，不承诺冻结任意执行器内存。

切模型只能发生在已验证兼容的调用/任务边界，记录实际版本、能力和价格；网关不能仅替换字符串而忽略协议、工具或认证差异。

09

契约、制品发布与运行恢复

不可变发布链路

契约/提供方 PR → 候选制品与摘要 → 提供方验证 + 登记消费者回归
   → 发布同一已验证制品 → 消费方升级 PR → staging → 人工生产流程

按实际技术栈选择 schema、SDK 或包，不预设四项目均用 npm。依赖清单显式登记；“全部回归”只代表登记消费者范围，不能等同所有行为都有测试。

已发布版本不覆盖、不复用版本号。坏版本停止推广并弃用，回到稳定指向或发布修复版；不将 npm unpublish 当日常回滚。撤包有平台条件，且不能撤销已安装依赖。npm 撤包规则

对象 恢复方式 前提
契约/依赖包 回退锁文件与兼容版本，重建 旧制品可取、构建可复现。
运行服务 回到已验证镜像摘要和配置 数据/schema 兼容，流量与健康检查可恢复。
数据库 兼容扩展、迁移、切换、延后收缩；必要时前向修复或备份恢复 评估停机、数据损失和恢复点，破坏性变更专项审批。
设计系统 回退兼容包或发布修复版 组件、token 及消费方构建兼容。

破坏性契约用新旧并行/适配期：先扩展提供方，再迁移消费者，确认旧依赖退出后收缩。模板、契约、项目按兼容矩阵和依赖图升级，不无条件要求“先模板后契约”。恢复目标经演练确定，不承诺所有场景 10 分钟恢复；安全恢复步骤不能依赖额度耗尽后再调用模型生成。

10

经验闭环与规则治理

任务终态与 outbox 事件同事务提交；后台消费者按事件键去重，收集失败、人审和修复证据。Retro 故障或预算不足只影响复盘进度，不改变交付终态。

脱敏证据 → 候选经验 → 核实适用范围/冲突/复现 → 审核或评测 → 受控采用
                         └→ 证据不足：继续候选或归档
已采用经验 → 效果观察 → 修订 / 撤销 / 硬化为门禁

候选包含 source_task、失败与修复证据、适用项目/角色/版本、触发条件、具体动作、审核及撤销记录。重复出现两次只触发复核；同源错误被反复复制不算独立证据。

AGENTS.md、正式规范与 ADR 由授权流程维护。Retro 不能直接改这些规则，也不将原始日志或候选经验自动注入 system prompt。审核经验以带出处的辅助上下文提供，不覆盖权限规则及当前任务指令。跨项目推广重新验证和审核；权限、生产、恢复或架构规范变更走对应批准流程。

按任务相关性选取经验，记录注入条目版本与 token 量；限制配置化，不把行数当精确 token 数。低频高影响约束不能仅因十次任务没命中就淘汰。机器可判定的稳定规则优先进入门禁。撤销经验保留原因和影响任务列表；每月抽查不替代采用前审核。

11

模板版本、复现与评测

每次运行冻结实际版本

项目可设置升级策略，但任务启动时保存确切模板版本/哈希、门禁版本、模型配置、执行器版本、契约、依赖锁文件、经验条目和 base_commit。挂起恢复检查兼容性，不在人审等待时自动替换环境。

若采用 npm SemVer，^1.2 允许 minor 升级；~1.2.0 可表达 patch 范围，但仍需记录实际解析版本。npm SemVer

变更 策略
输出、交接契约或权限语义不兼容 Major，提供迁移及兼容检查，项目显式批准。
新能力/新门禁 按实际兼容性判定；新增阻断规则可能破坏旧任务。
措辞修正 可记 Patch，但模型行为可能改变，仍需最低回归和分批推广。

评测和推广

2–3 个任务只做冒烟。固定评测集覆盖真实类型、难度、异常和历史回归；新旧版本使用相同输入与环境，重复运行并记录波动、样本量及失败原因。

先满足权限、安全、兼容和验收底线，再比较包含返工的总费用、时延与人工投入。加权分数可辅助排序，不掩盖关键退化。经过候选评测、低风险试用、人工审查和分批升级，保留上一可用版本与回退路径。

12

指标、观测与容量

指标 定义与口径
有效交付率 固定观察窗口中，在约定时间/预算内通过验收数 ÷ 纳入试点任务数；公开排除规则，取消/未完成单列，不只统计成功结束任务。
单位有效交付成本 同组全部执行费用（含失败、重试、评测摊销和复盘）÷ 验收通过数；同时报告总费用和成功数。
人工投入 每任务介入次数、主动处理分钟数，与人审等待分开。
周期时长 接收至交付 P50/P95，拆分排队、执行、人审和返工。
同类错误发生率 适用规则的任务中发生对应错误的比例，说明适用性判定及抽查。
恢复质量 分场景统计成功率、耗时、重复副作用、制品丢失和人工对账。
预算质量 准入拒绝、预占滞留、账单偏差、超限金额，按项目/模型/任务分组。

弃用“重犯数 ÷ 全部失败数”作为学习改善主指标：新错误减少可能让它上升。没有对照时，不把未犯错归因于记忆；通过条目检索/采用记录、配对实验与人工抽查评估。条目数只描述库存。

运行关联 project/task/revision/node/attempt/lane、trace_id、epoch、制品和操作标识。审批、预算、状态转换、部署与错误事件完整留存；高体积模型 Trace 可抽样，敏感数据脱敏并设保留期。

首版视图只需当前状态、阻塞原因、待审批、预算和证据链接。依赖图、热力图、经验趋势由实际排障需求推动。容量由 CPU/内存、供应方限制、构建时间、连接、端口和预算共同决定；按项目设上限/保底、公平队列与背压，不把 16 槽当实测能力。

13

实施路线与退出标准

估算窗口为“3–4 个工作日准备 + 7 个实施周”，准备期不计入七周；实际排期取决于人员与环境。按退出条件推进，不因日历到期跳过验证。

阶段 建议窗口 建设重点 退出条件
P0 可行性 准备期 确认栈/OS/认证；真实调用、权限、用量、预算最小验证；登记审批人 调用可归因，越界被阻断，至少一种执行器可停止/恢复；未知项有责任人。
P1 单项目可靠闭环 Week 1–2 账本、租约、审批哈希、门禁、staging，前置崩溃和预算演练 代表性任务通过；恢复不重复操作；审批变更失效；额度不足停止新调用。
P2 双项目验证 Week 3–4 契约候选、回归、环境隔离、升级 PR、最小任务视图 单方失败不污染另一方；坏候选不推广；旧版本可重建；恢复证据齐全。
P3 四项目扩展 Week 5–6 公平调度、配额、容量，必要时升级存储/队列 并发满足预算和隔离；公共故障可暂停/恢复；发生数据迁移须验收。
P4 效果评估 Week 7 及以后 固定评测集、模型/模板比较、经验审核及成本复盘 相对基线报告结果与不确定性，不以七角色齐备或记忆条数强行通过。

平台负责人负责协议及证据，项目负责人负责业务验收，安全/发布责任人负责权限及部署；具体人选 P0 填写。复杂看板、自动跨项目经验晋升、多机队列、第二执行器全面接入均可后置。

故障验收场景与证据

下列场景当前全部待执行。每次记录环境、版本、注入时点、预期/实际状态、日志、外部结果、费用和负责人；不能用文档检查替代运行演练。

编号 场景 通过条件
AC-01 部署成功后、记账前杀死 Orchestrator 恢复查询同一结果，不重复部署；不可查询时对账，不盲重试。
AC-02 失联 Worker 仍运行，平台接管 拒绝旧 epoch 提交/副作用；旧进程隔离，新 attempt 不共享可写资源。
AC-03 多请求竞争最后预算 原子准入不超承诺上界，拒绝进入 paused_budget，无重试风暴。
AC-04 流式断连、取消回执丢失、跨日 不提前释放可能已消费预占；对账后结算，不跨日重复发放原额度。
AC-05 审批后新增提交或修改部署配置 旧审批不放行新制品，重跑受影响门禁及审批。
AC-06 shell、工具、符号链接尝试越界 实际 OS 硬限制有效，凭据/网络/共享资产保护及审计有效。
AC-07 不兼容契约候选 消费者回归失败阻止推广；旧依赖可安装重建，不依赖撤包。
AC-08 服务回退时数据已变化 按声明兼容方案恢复或前向修复，阻止不安全降级并转人工。
AC-09 任务完成后 Retro 宕机并重复消费 交付不回退，事件可重试，候选不重复，不自动改 AGENTS.md。
AC-10 两 lane 并发 E2E 后触发清理 数据/端口/环境不污染，等待/暂停/对账 worktree 不误删。
AC-11 从备份恢复状态库/checkpoint 与制品、外部结果对账，不重复副作用，记录恢复点和耗时。
AC-12 挂起期间升级模板/经验/执行器 原配置可追溯，兼容恢复；必要时新修订重新验收。

P1 至少通过 AC-01～06、09、12；P2 验证 AC-07、08、10、11 后再扩至四项目。每项包括失败处理路径，单次成功演示不证明长期故障率。
